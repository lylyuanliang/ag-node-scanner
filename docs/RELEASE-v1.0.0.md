# Clash 节点体检器 v1.0.0

首个版本。给 Clash 节点做一次真实体检：**延迟、速率、出口 IP、IP 纯净度**全部实测，不靠 IP 段猜。

![主界面](screenshots/01-overview.png)

| `SHA256` | `8A5A2F657602D8644E884B11F14CEFEBDC89F33CEC4EC6437432AF69B0CCF07B` |

**运行前提**：已安装 [Clash Verge](https://github.com/clash-verge-rev/clash-verge-rev)。程序会自己找它自带的 `verge-mihomo.exe` 和运行态配置。

## 这一版能干什么

- **实测延迟**：临时内核的 delay 测试，目标 `www.gstatic.com/generate_204`
- **实测速率**：真的下载 384 KB，按首字节之后的耗时折算
- **实测出口 IP**：真的从该节点出去，看外部看到的公网 IP
- **IP 纯净度 0-100**：参考 ippure 的维度，融合欺诈分、机房属性、代理标记、代理历史

实测能分出来的差距：

| 节点 | 纯净度 | 欺诈分 | 标记 |
|---|---|---|---|
| 台湾1 | 100 | 0 | — |
| 香港原生IP-1 | 91 | 1 | Go Proxies residential |
| 美国洛杉矶-1 | 9 | 80 | 机房 + ProxySeller residential |

同样是「原生 IP」标签，被住宅代理转卖过的那个，纯净度直接掉 9 分；被当代理池的美国节点掉到 9。

## 安全边界

- **不碰账号**：全程不登录、不带任何凭据，不会被服务商标记
- **不干扰现有 Clash**：另起独立 mihomo 实例（独立端口、独立临时目录、单条 MATCH 规则），测完即删；你的 TUN、分流、当前节点全程不动

## 性能

完整一轮（41 个节点、深测 20 个）：**197 秒**。

靠的是延迟阶段 12 并发、静态补查后台化、属性/纯净度流水线化、每个网络动作加墙钟上限。

## 界面

![结果表](screenshots/04-table.png)

- 五列检测项可勾选，右侧实时估算耗时
- 双层进度：总进度 + 阶段进度 + 剩余时间 + 当前节点与步骤
- 不可用节点任何排序都沉底，评分 0、结论「连不上」
- 七个快捷筛选：全部 / 美国 / 亚洲 / 延迟<300ms / 评分≥42 / 纯净度≥70 / 纯净度<40

## 明确测不了的

Google 的「地区不支持」400 校验发生在**鉴权之后**，不带账号请求只会拿到 401。所以本工具不声称能测出 200/400，「域名可达」列只代表域名连不连得上。

## 已知限制

1. 仅支持 Clash Verge
2. 测速为 384 KB 抽样，被 8 秒墙钟截断时显示速率下限
3. 只深测延迟最低的前 20 个节点，避免白耗流量
4. 纯净度数据来自 scamalytics 与 ip-api，受其限速约束
